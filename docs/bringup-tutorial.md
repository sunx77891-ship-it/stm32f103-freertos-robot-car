### 0.2 按实际代码要求准备硬件

**目标**

一次性确认主控、驱动、电机、编码器和 IMU 是否满足原工程的硬性条件，避免买回不兼容器件后才发现无法直接使用。

**前置条件**

- 已确认要跑通的是原工程，而不是改成 TB6612、MPU6050、JY901S 或单相测速电机方案。

**具体任务**

1. 按手册的必需硬件清单准备：

   | 器件 | 手册要求 |
   |---|---|
   | STM32F103RCT6 最小系统板 | 8 MHz 外部晶振，256 KB Flash，按 STM32F103RC 配置 |
   | ST-Link V2、DAPLink 或 J-Link | 支持 SWD |
   | 两个 A4950 单路 H 桥模块 | 两个电机各一个 |
   | 两个带 AB 相编码器的减速电机 | 编码器必须输出 A、B 两相 |
   | 零刻/类六轴串口 IMU | 115200、5 字节帧、帧头 `0x5A` |
   | 小车底盘、轮子和联轴器 | 双轮差速结构 |
   | 12 V 电池或稳压电源 | 不从 ST-Link 给电机供电 |
   | 5 V/3.3 V 降压模块 | 给 MCU、IMU、OLED 供电 |
   | USB 转 TTL 模块 | 3.3 V 电平，115200，连接 USART1 的 PB6/PB7 |

2. 为后续验收另行准备手册建议的观察设备：
   - USB 逻辑分析仪。
   - 万用表。
   - 备用 STM32 板和备用 A4950 模块。
   - 0.96 寸 SSD1306 OLED。
   - 按键、LED、蜂鸣器。

3. 购买前重点核对四件事：
   - 电机编码器是 A/B 两相。
   - IMU 输出 `0x5A 0xAA` 和 `0x5A 0xBB` 帧。
   - OLED 是 I2C 地址 `0x3C`，不是 SPI。
   - 电机驱动是 A4950；若用 TB6612，必须准备修改代码，不能直接照搬原接线。

**关键配置或操作**

- 电机电源和 MCU 电源必须共地。
- USB 转 TTL 必须是 3.3 V 电平。
- 不从 ST-Link 给电机供电。

**预期结果**

- 采购单与手册要求对应。
- 不会把普通 MPU6050 I2C 模块接到 USART3 后期待原代码工作。
- 不会把只有单相测速信号的电机当作 AB 相编码器电机使用。

**验收方式**

- 每个带电机器件都能对应到手册的引脚表或协议要求。
- 采购前四项硬性确认全部完成。
- 若任何一项无法确认，不进入接线和烧录阶段。

**需补充**

- 手册把 OLED、按键、LED、蜂鸣器列在“建议增加”中，但“只烧录”和串口阶段的验收明确依赖 OLED、蜂鸣器；后续手动控制还依赖按键。若没有这些器件，需要补充替代验收方法。

### 0.3 采购前向 IMU 卖家确认协议

**目标**

确保买到的串口姿态模块能被原工程 `EIDE/IMU/Gyro.c` 直接解析。

**前置条件**

- 已找到候选 IMU，但尚未直接把“零刻/类六轴串口 IMU”当成充分条件。

**具体任务**

1. 向卖家确认模块输出 `5A AA` 和 `5A BB` 帧。
2. 确认波特率必须为 115200。
3. 确认模块 TX 应接 STM32 USART3 RX，也就是 PB11。
4. 确认模块和 STM32 必须共地。
5. 如果候选模块是 JY901S，要明确它不是原代码可直接兼容的默认选项；使用它需要重写 `EIDE/IMU/Gyro.c` 的协议解析部分。

**关键配置或操作**

IMU 帧格式：

```text
字节0  字节1  字节2  字节3  字节4
0x5A   TYPE   LOW    HIGH   SUM
```

- `TYPE = 0xAA`：角速度 Wz。
- `TYPE = 0xBB`：航向角 Yaw。
- `raw = (int16_t)((HIGH << 8) | LOW)`。
- 校验：前 4 字节累加，取低 8 位。
- Wz：`raw / 32768.0 * 2000.0`，单位 `°/s`。
- Yaw：`raw / 32768.0 * 180.0`，单位 `°`。

**预期结果**

- 卖家能明确确认两种帧头和 115200 波特率。
- 已知道模块 TX 接 PB11、模块与 STM32 共地。

**验收方式**

- 商品说明或卖家回复能逐项对应“帧头、类型字节、波特率、接线方向、共地”。
- 无法确认协议时不购买该 IMU，也不进入后续 IMU 调试。

**需补充**

- 具体商品型号、供电电压、接插件定义、安装方向、Yaw 零点、输出频率和校准方法均未在手册中给出。

## 1. 总体执行路线

严格按照下面的顺序推进。每一阶段通过验收后，再进入下一阶段。

| 阶段 | 主要工作 | 阶段出口 |
|---|---|---|
| 0 | 版本边界、采购和 IMU 协议确认 | 硬件兼容，IMU 协议明确 |
| 1 | 安装 VS Code、EIDE、AC5、DFP 和下载器驱动 | 工具链可配置 |
| 2 | 获取源码、打开 EIDE 工作区、编译 | 生成构建产物 |
| 3 | 不接电机，只检查和测试电源 | 12 V、5 V、3.3 V、无短路、共地均确认 |
| 4 | 不接电机，烧录并验证启动 | OLED 显示 `System Ready`，蜂鸣器三声 |
| 5 | 验证 USART1 命令和输出 | `K1\r\n`、`K2\r\n`、`K3\r\n` 有预期响应 |
| 6 | 验证 IMU 串口帧 | 帧头正确，转动时 Yaw/Wz 变化 |
| 7 | 架空、逐电机验证方向和编码器 | 方向、符号、刹车、共地均通过 |
| 8 | 架空验证速度闭环 | 目标速度从 10 开始，启动和停止可控 |
| 9 | 先架空、后落地验证矩形路径 | 状态机、转向方向和路径动作正确 |
| 10 | 可选 MATLAB 辨识和调参 | CSV 与模型文件可用 |
| 11 | 手册建议的保护与工程化改造 | 仅作为后续阶段，不冒充原工程已有能力 |

**总原则**

- 第 3 阶段之前不接电机。
- 第 4 阶段只烧录，不接电机。
- 第 5 阶段先验证命令通道，不只盯着电机。
- 第 6 阶段发现 IMU 协议不一致时，先改 `Gyro.c`，不要继续调 PID。
- 第 7、8、9 阶段电机测试必须架空轮子。
- K3 只是 `Key_ScanTask` 内的软件急停逻辑，不是硬件急停。
- 任何时候不要把“能烧录”当成“底盘闭环已经通过”。

## 2. 阶段一：准备开发环境

### 2.1 安装手册要求的必装工具

**目标**

建立与仓库结构匹配的编译、下载和串口调试环境，并且这套环境能被逐项检查，而不是“感觉装好了”。

> 本节标注约定：〔手册〕指原项目手册给出的依据；〔外部〕指教程补充的、可在公开文档中查证的通用事实（来源见本节末）；未标注的是本教程针对本工程条件做的判断。补充内容不改变手册结论，只把“怎么做、怎么验”补到可执行。

**前置条件**

- 阶段 0 出口已通过：0.2 的硬件清单已逐项确认，且下载器已确定为 ST-Link V2 / DAPLink / J-Link 中的具体一种（依据 1. 总体执行路线的阶段出口、0.2 的硬件清单）。
- 已确认本工程只走 VS Code + EIDE + AC5 路线。检查方法：仓库中存在 `EIDE/RCT6_2motocar_PIDbymatlab.code-workspace`，且不以 `MDK-ARM/*.uvprojx` 为入口（依据 0.1 的关键配置或操作）。本机若另有 CMake 或 Makefile 的 STM32 工程不影响，只要不把那些工程当作本工程的构建入口——这条替代了原来“电脑尚未按…路线准备”这种无法验收的表述。
- 环境前提：Windows 10/11 64 位，可联网，空闲磁盘不少于 6 GB，能注册并登录 ARM 与 ST 账号（AC5 与器件包要从官网下载）〔外部〕。
- 授权前提：AC5 需要有效许可才能编译超限代码；未授权或评估状态下存在 32 KB 代码上限，本工程固件是否超限要到 3.3 编译后看构建输出的 Code + RO Data 才能确认〔外部〕。手里没有可用许可时，先解决授权再动手，否则会在链接阶段卡住。

**具体任务**

1. 安装 Git（只为 3.1 克隆源码，不参与编译，可以最后再做）。
   - 从 `https://git-scm.com/download/win` 下载 64 位安装包，安装时保持默认选项。
   - 验收：命令提示符执行 `git --version`，能打印版本号。

2. 安装 VS Code。
   - 从 `https://code.visualstudio.com` 下载 Windows x64 安装包；安装路径不要含中文和空格〔外部〕。
   - 验收：帮助 → 关于，能显示版本号。

3. 在 VS Code 安装扩展 `cl.eide`（Embedded IDE）。
   - 扩展面板搜索 `Embedded IDE`，发布者为 `cl.eide`，点击安装。
   - 首次启动该扩展会自动下载 eide-binaries 和 .NET 6 x64 运行时；运行时安装完成后必须重启全部 VS Code 窗口，否则扩展会报找不到 runtime〔外部〕。
   - 验收：活动栏出现 EIDE 图标，OPERATIONS 视图可见；顺手记录扩展版本号。
   - 这一步需要联网；网络受限时可在扩展页用“从 VSIX 安装”离线安装。

4. 安装 Arm Compiler 5.06（AC5）——本节最关键、也最容易卡住的一步。
   - 事实前提：AC5 自 Keil MDK 5.37 起不再随 MDK 安装；5.06 update 7（build 960）是它的最后一个版本，已停止维护〔外部〕。
   - 路线 A：本机已装 Keil MDK〔外部〕。
     - MDK 5.36 及更早：AC5 在 MDK 安装根目录下的 `ARM\ARMCC`（通常是 `C:\Keil_v5\ARM\ARMCC`），直接用这个目录。
     - MDK 5.37 及更新：按 Arm 官方步骤把 AC5 补装到 MDK 的 `ARM` 子目录，例如 `C:\Keil_v5\ARM\Arm_Compiler_5.06u7`。
     - 不要用 EIDE “安装实用工具”里下载的独立版 AC5：它需要许可证，且会与已装 Keil 的 AC5 冲突，典型表现是编译时报 license 错误〔外部〕。
   - 路线 B：本机没有装 Keil MDK〔外部〕。
     - 解压工具：官方包是 zip→tgz→tar 三层。Windows 10/11 自带的 `tar`（bsdtar）能直接读 zip 和 tgz，三层可以一路解到底，不装 7-Zip 也能完成（本机已实测）；想要图形界面再装 7-Zip，非必需。
     - 打开 Arm 的 Arm Compiler 下载索引页，在“Releases without Functional Safety qualification or certification”一段找到 Arm Compiler 5.06 update 7 (build 960)，Revision 选 `r5p6-07rel1`，下载 Win32 包（需登录 ARM 账号）。
     - 解压后进入 `Installer` 目录，以管理员身份运行 `setup.exe`。
     - 安装目录必须落在 Keil 的 `ARM` 子目录下（如 `C:\Keil_v5\ARM\Arm_Compiler_5.06u7`）。装到 `C:\Program Files (x86)` 会报 `C9555E` 或 `C9511E`〔外部〕。注意：本机实测把 u7 装进 `C:\Program Files (x86)` 后会直接报 `C9555E`（找不到许可）；**已装 MDK 的机器应直接用 MDK 自带的 `ARM\ARMCC`，不必另装一份**。
     - 也可以改用 EIDE 的“安装实用工具”装 AC5，装完同样要重启 VS Code；两种方式不要混用。
   - 验收（原文只写“电脑中有 AC5”，这里补上可操作的检查）：
     1. 目录检查：安装目录下存在 `bin\armcc.exe`、`bin\armasm.exe`、`bin\armlink.exe`。
     2. 命令行检查：执行 `armcc.exe --version`，输出应为 `5.06 update 7 (build 960)`。
     3. EIDE 检查：OPERATIONS → `Configure Toolchain` → 选 `ARMCC V5` → 选择编译器根目录（含 `bin` 的那一级，不是 `bin` 本身）；路径有效时该项右侧显示 ✔，无效显示 ✗〔外部〕。
     4. 许可检查：没有有效许可时，编译或链接会报 license 类错误；此时先处理授权，不要往 2.2 走。

5. 安装 STM32F1 器件包（DFP），版本固定 2.3.0。
   - 版本决策：固定用 `Keil.STM32F1xx_DFP` 2.3.0，不追新版本，避免引入与 AC5、HAL 头文件版本相关的额外变量。唯一允许换版本的情形：装完在 EIDE 里选不到 STM32F103RC，或 3.3 编译时报器件包头文件相关错误。
   - 获取：`https://www.st.com/resource/en/pack/Keil.STM32F1xx_DFP.2.3.0.pack`（备用：`https://keilpack.azureedge.net/pack/Keil.STM32F1xx_DFP.2.3.0.pack`）。
   - 顺序说明：EIDE 的器件包入口在“工程页”里，所以这一项要么在 3.2 打开工作区之后做，要么先只下载 `.pack` 文件、等工程打开后再装。其余各项与仓库无关，不受影响。
   - 安装：EIDE 工程页 “Chip Support Package” 右侧 `+` → From Disk → 选中下载的 `.pack` 文件〔外部〕。
   - 离线落位（等价做法，本机实测）：`.pack` 本身就是 zip，直接解到工程 `EIDE/.pack/Keil/STM32F1xx_DFP.2.3.0/`，与工程 `eide.yml` 里的 `packDir` 一致即可，不必走界面。适合界面安装被卡、或网络不稳定时使用。
   - 落点：EIDE 会把它解压到工程内的 `EIDE/.pack/`，该目录被 `.gitignore` 排除（见本节“关键配置或操作”），所以重新 clone 或换电脑后要重装一次。
   - 分工：本节只“取得并装上”；2.2 第 4 步只“确认工程已选用该包”，不重复安装。
   - 验收：EIDE 器件选择里能选到 `STM32F103RC`；`EIDE/.pack/` 下出现 DFP 目录。若此时还没打开工作区，此项先挂起，在 3.2 之后补验。

| 动作 | 电机 A | 电机 B |

TIM3 计数值 -> current_b

**验收方式**

## 附录 F：建议的阅读顺序

在硬件尚未到齐、不能立即上电时，可以按手册“第一周学习任务”理解代码：

1. 第 1 天：克隆仓库，画出三个任务和数据流，找到 `main.c`、`freertos.c`、`Ctrl.c`、`Gyro.c`。
2. 第 2 天：阅读 TIM1、TIM2、TIM3 配置，计算 20 kHz PWM，理解编码器 TI12 模式。
3. 第 3 天：阅读 `MotorDrive.c`，画出正转、反转、刹车时四路 PWM 的电平。
4. 第 4 天：阅读 `Gyro.c`，手工解析一帧 `5A AA L H SUM`，确认 IMU 型号和协议。
5. 第 5 天：阅读 `Ctrl.c`，画出速度环、位置环、航向环、角速度环框图。
6. 第 6 天：安装 EIDE 和 AC5，编译原工程，记录编译错误和解决过程。
7. 第 7 天：只接 MCU、OLED、USART1，验证启动、按键命令和串口输出，暂不接电机。

## 最后结论

这套原工程的正确落地顺序不是“先改 PID”，而是：

1. 确认代码边界、许可证风险和硬件兼容性。
2. 配置 VS Code + EIDE + AC5 + STM32F1xx_DFP。
3. 从 EIDE 工作区编译。
4. 不接电机检查电源。
5. 不接电机烧录并检查 `System Ready`、三声蜂鸣和调试。
6. 验证 USART1 命令。
7. 验证 IMU 帧协议。
8. 架空逐电机验证方向和编码器。
9. 架空验证速度闭环。
10. 先架空、再落地验证自动矩形路径。
11. MATLAB、超时保护、硬件急停、CRC、看门狗和 ROS2 属于后续阶段，不能冒充原工程现成功能。

只有在原工程主线全部验收后，才建议按手册结论继续：

1. 先用原代码跑通硬件。
2. 按手册逐模块讲清楚。
3. 从空工程重建核心功能。
4. 增加超时、CRC、看门狗和测试工具。
5. 再把串口协议升级为 Linux/ROS2 可直接调用的底盘接口。
